# HANDOFF — снимок состояния

**Дата:** 2026-06-02
**Проект:** Splithub_api_telegram_me — отдельный Telegram-сервис ежедневных остатков
для SplitHome. Подробности и правила — в `CLAUDE.md`, дизайн — в `docs/PLAN.md`.

## Контекст создания

Фичу «ежедневный отчёт об остатках в Telegram» сначала сделали внутри проекта сайта
(`B2B_split_breeze_v2`) как Celery-задачу. По решению владельца вынесли в **отдельный
проект** ради независимого деплоя. Правки из папки сайта откатили — там осталась
только 1 строчка (см. ниже). Прод сайта `splithome.ru` при этом был и остаётся жив
(локальные правки в него не деплоились).

## Что сделано (этот проект)

- Самостоятельный сервис: `stock_report_bot/{config,db,report,telegram,main}.py`.
- Читает БД сайта (read-only), собирает отчёт, шлёт владельцу в личку.
- Тесты `tests/test_report.py` — **4/4 проходят** (чистый Python, без БД):
  группировка по поставщику, количество (Крым vs сумма для Бриза), чанкинг, пустой случай.
- Документация: `README.md`, `CLAUDE.md`, `docs/PLAN.md`.
- `.env`/`.env.example`: `chat_id=1264067528` вписан; секреты пустые (заполнить).

## Состояние

- ✅ Логика отчёта проверена тестами.
- ⏳ **End-to-end (с реальной БД и Telegram) ещё НЕ прогонялся** — нужно заполнить
  `.env` (DB_PASSWORD, TELEGRAM_BOT_TOKEN из `/opt/oasis/.env` сайта) и запустить
  `python -m stock_report_bot.main`.
- ⏳ Не задеплоен (нет cron/systemd на сервере).

## Связанный репозиторий сайта (важно)

В сайте (`github.com/flycited2-dotcom/split-shop_claude`, ветка `develop`) лежит
**незакоммиченный** фикс опт-цены Бриза: `apps/sync/tasks.py::sync_stock` + тест
`apps/sync/tests/test_sync_stock_price.py`. Чтобы сервис показывал **правильную
опт-цену Бриза**, этот фикс нужно закоммитить и задеплоить в проде сайта.
(На момент хендовера — не закоммичен.)

## Следующие шаги

1. Заполнить `.env` секретами из `/opt/oasis/.env` сайта.
2. `python -m stock_report_bot.main` — убедиться, что отчёт приходит в личку.
3. Закоммитить+задеплоить фикс Бриза в репозитории сайта (иначе опт-цена Бриза неверна).
4. Настроить расписание на сервере (cron/systemd, 09:00 МСК) — см. README.
5. Проверить связность с БД (контейнер `db`: своя docker-сеть либо публикация порта).
