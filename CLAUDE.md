# CLAUDE.md — контекст проекта для Claude Code

## Что это

**Splithub_api_telegram_me** — самостоятельный сервис: раз в сутки собирает список
товаров в наличии и шлёт его владельцу в **личный** Telegram. Один отчёт = строки
вида `• Бренд Модель — опт-цена ₽ — количество шт.`, сгруппированные по поставщику,
разбитые на несколько сообщений (лимит Telegram — 4096 символов).

Проект сознательно **отделён** от сайта SplitHome, чтобы деплоиться независимо
(не нужно передеплоивать сайт ради Telegram-задачи).

## Главное: зависимость от сайта

Сервис **только читает** базу сайта SplitHome (PostgreSQL, read-only). Сам он не
синхронизирует поставщиков — данные (товары, остатки, цены) в БД кладёт
синхронизация сайта.

- **Репозиторий сайта:** `github.com/flycited2-dotcom/split-shop_claude` (локально —
  `C:\Users\user\Documents\GitHub\B2B_split_breeze_v2`).
- **Таблицы, которые читаем:** `catalog_product`, `stock_stock`, `stock_warehousestock`.
- ⚠️ **Опт-цена — у каждого поставщика свой источник; в `price_wholesale` НЕ всегда опт:**
  - **Бриз:** в БД у него `price_wholesale` = розница (`ric`). Опт (base/закупку) Бриз
    отдаёт только в своём API `/leftoversnew/` — сервис берёт его напрямую через
    `stock_report_bot/breez.py` (по `nc_code`), при сбое/без ключа откат на цену БД.
    Ключ — `BREEZ_AUTH_HEADER` в `.env`. (Фид Бриза НЕ содержит NC Русклимата.)
  - **Русклимат:** в `price_wholesale` тоже лежит розница (= `ric`), а настоящий опт
    («Ваша цена» портала) — в `stock_stock.price_base` (per-warehouse). Сервис берёт
    `price_base`, откат на `price_wholesale`, если пусто. (Проверено: `price_base`
    совпадает с «Ваша цена» b2b.rusklimat.com, NC-коды совпадают.)
  - **Daichi:** опт корректно лежит в `price_wholesale`.

## Бизнес-правила отчёта (НЕ менять бездумно)

- **Состав:** «только Крым (Симферополь) для ВСЕХ поставщиков», включая Бриз. Берём
  из `stock_stock.warehouse='Симферополь'` — сайт ставит так только при наличии
  крымского остатка (для Бриза крымский склад «…Крым» ловится regex `_CRIMEA_RE`
  сайта в `warehouse_stock.py`). Материк (Шерризон/Ростов/Киржач) и «под заказ» НЕ
  включаем.
- **Категории/типы:** только кондиционеры нужных типов — Бытовые сплит (id 2),
  Полупромышленные (id 6: кассетные/канальные/напольно-потолочные/колонные),
  Мобильные (id 7). Дополнительно `btu_calc > 0` (есть мощность охлаждения → это
  кондиционер, а не аксессуар: у моек/развальцовок/насосов/шлангов btu пуст) и
  денилист `db.EXCLUDE_TITLE_PATTERNS` (мультисплит + аксессуары с ошибочным btu:
  виброопоры/охладитель воздуха/зимний комплект). См. `db.py`.
- **Количество:** крымский остаток (Симферополь) для всех.
- **Наименование/формат:** жирный бренд (`catalog_brand.title`) + `title` (бренд
  впереди — в title его часто нет). Эмодзи на поставщика (`report.SUPPLIER_EMOJI`),
  сортировка/группировка по бренду. Полоски-разделители на всю ширину: тонкая
  (`report.ITEM_DIVIDER`) после каждой позиции, двойная (`report.BRAND_DIVIDER`)
  между брендами.
- **Опт-цена:** Daichi — `catalog_product.price_wholesale` из БД; Бриз — base из Бриз
  API по `nc_code` (`breez.py`); Rusklimat — `stock_stock.price_base` (в БД у Бриза и
  Русклимата `price_wholesale` = розница), с откатом на `price_wholesale`. См.
  `report._price_for`.
- Реализация: фильтр в `stock_report_bot/db.py` (Симферополь + категории + бренд);
  количество — `report._qty_for`, строка — `report._product_line`.

## Структура

```
stock_report_bot/
  config.py    — чтение .env (БД + Telegram), python-decouple
  db.py        — один SQL-запрос остатков к БД сайта (read-only)
  breez.py     — опт-цена (base) Бриза напрямую из Бриз API; ЧИСТЫЙ _parse_leftovers
  report.py    — сборка текста: группировка/цена/чанкинг, ЧИСТЫЕ функции
  telegram.py  — send_telegram(text, chat_id); charset=utf-8 ОБЯЗАТЕЛЕН
  main.py      — точка входа: fetch → build → send
tests/test_report.py   — unittest логики отчёта (без БД и сети)
tests/test_breez.py    — unittest парсинга Бриз API (без сети)
docs/PLAN.md
```

## Запуск / тесты

```bash
pip install -r requirements.txt
cp .env.example .env          # заполнить DB_PASSWORD и TELEGRAM_BOT_TOKEN
python -m stock_report_bot.main          # собрать и отправить один раз
python -m unittest discover -s tests -v  # тесты логики отчёта
```

## Конвенции / подводные камни

- **Telegram + кириллица:** отправлять с `Content-Type: application/json; charset=utf-8`
  и `json.dumps(..., ensure_ascii=False)`. Без charset кириллица ломается через
  socat-proxy на VPS (проверено на сайте).
- **Чанкинг:** одно сообщение ≤ ~3900 символов, режем по границам строк.
- **chat_id владельца:** `1264067528` (личный чат). Бот не может написать первым —
  владелец должен был хотя бы раз написать боту.
- **Секреты** (DB_PASSWORD, TELEGRAM_BOT_TOKEN) — только в `.env` (gitignored),
  брать из `/opt/oasis/.env` сайта. В git/доки НЕ коммитить.
- **Расписание:** cron/systemd на 09:00 МСК (примеры в README.md). На сервере сервис
  должен видеть контейнер БД `db` (своя docker-сеть или опубликованный порт).
