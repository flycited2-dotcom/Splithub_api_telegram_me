# SplitHome — Telegram-сервис ежедневных остатков

Самостоятельный сервис: раз в сутки собирает список товаров в наличии и шлёт его
владельцу в **личный** Telegram. Не зависит от деплоя сайта — только читает его БД.

Строка отчёта: `• Бренд Модель — опт-цена ₽ — кол-во шт.`, сгруппировано по поставщику,
несколькими сообщениями (лимит Telegram 4096 символов).

## Состав отчёта (бизнес-правило)

«**Только Крым (Симферополь) для всех поставщиков**»:
- Все поставщики (Rusklimat / Daichi / Бриз) — только то, что есть в Крыму (склад
  «Симферополь»), количество = крымский остаток. Материк (Шерризон/Ростов/Киржач) и
  «под заказ» НЕ включаем.
- Только кондиционеры нужных типов: Бытовые сплит / Полупромышленные (кассетные,
  канальные, напольно-потолочные, колонные) / Мобильные. Аксессуары и инструменты
  (мойки, развальцовки, насосы, шланги…) отсеяны фильтром `btu_calc > 0` (нет
  мощности охлаждения → не кондиционер); мультисплит-системы исключены.
- Формат: эмодзи у каждого поставщика, **жирный бренд** впереди наименования,
  сортировка/группировка по бренду, полоски-разделители между брендами.

## Зависимость от сайта

Данные (товары, остатки, цены) в БД готовит синхронизация сайта SplitHome. Сервис
их только читает. Исключения по опт-цене (в `price_wholesale` не всегда опт):
- **Бриз** — в БД розница; опт (base) сервис берёт напрямую из Бриз API
  (`stock_report_bot/breez.py`, по `nc_code`), откат на БД. Нужен `BREEZ_AUTH_HEADER`
  в `.env` (из `/opt/oasis/.env` сайта).
- **Русклимат** — в `price_wholesale` тоже розница; опт («Ваша цена» портала) лежит в
  `stock_stock.price_base`, сервис берёт его, откат на `price_wholesale`.
- **Daichi** — опт корректно в `price_wholesale`.

## Установка

```bash
python -m venv .venv && . .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env      # заполнить DB_PASSWORD и TELEGRAM_BOT_TOKEN из /opt/oasis/.env сайта
```

## Запуск

```bash
python -m stock_report_bot.main        # собрать и отправить отчёт один раз (cron)
python -m stock_report_bot.bot         # интерактивный бот меню (постоянный процесс)
```

## Интерактивное меню с наценкой

Второй режим того же бота: команда `/menu` в личке владельца открывает кнопочное меню
**Поставщик → Бренд → Серия → % наценки (1–10)**. После выбора % бот берёт позиции
выбранной серии в наличии (Крым/Симферополь), прибавляет наценку к опт-цене (округление
вверх до …90) и присылает отдельным списком `Бренд Модель — цена-с-наценкой — кол-во`.
Работает по long-polling (`stock_report_bot/bot.py`), отвечает только владельцу. Серия:
поле `series` (Бриз/Daichi) либо парсинг из названия (Русклимат). Запускается отдельным
**systemd-сервисом** рядом с суточным отчётом (оба используют одну БД и `.env`, один токен —
конфликта getUpdates↔sendMessage нет).

## Расписание (раз в сутки, 09:00 МСК)

**cron** на сервере:
```cron
0 9 * * *  cd /opt/splithub_api_telegram && /opt/splithub_api_telegram/.venv/bin/python -m stock_report_bot.main >> /var/log/stock_report.log 2>&1
```

**systemd timer** (альтернатива): `stock-report.service` + `stock-report.timer`
с `OnCalendar=*-*-* 09:00:00` и `Persistent=true`.

> Подключение к БД: на сервере PostgreSQL — это docker-контейнер `db`. Либо
> опубликуйте порт (тогда `DB_HOST=localhost`), либо запустите сервис в той же
> docker-сети сайта с `DB_HOST=db`.

## Тесты

```bash
python -m unittest discover -s tests -v
```
Тесты `tests/test_report.py` проверяют группировку/количество/чанкинг на чистом
Python (без БД и сети).

## Структура

```
stock_report_bot/
  config.py     — чтение .env (БД + Telegram + Бриз API)
  db.py         — SQL-запрос остатков к БД сайта (read-only)
  breez.py      — опт-цена (base) Бриза напрямую из Бриз API
  report.py     — сборка текста (группировка/цена/чанкинг), чистые функции
  menu.py       — интерактивное меню: серия/иерархия/наценка/клавиатуры, чистые функции
  telegram.py   — Telegram: отправка отчёта + хелперы приёма/кнопок (UTF-8 charset)
  main.py       — точка входа отчёта: собрать → отправить (cron)
  bot.py        — точка входа меню: long-polling + кнопки (постоянный процесс)
tests/test_report.py    — логика отчёта (без БД и сети)
tests/test_breez.py     — парсинг Бриз API (без сети)
tests/test_menu.py      — логика меню/наценки/серии (без БД и сети)
docs/PLAN.md
```
