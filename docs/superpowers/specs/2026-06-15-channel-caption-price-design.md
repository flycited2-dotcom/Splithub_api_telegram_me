# Дизайн: подпись-прайс к карточке при публикации в канал

**Дата:** 2026-06-15
**Статус:** согласовано с владельцем, готово к плану реализации
**Затрагивает:** `Splithub_api_telegram_me` (Stock Bot) + `agent_convert_foto_rituailb2b2` (фотоген-агент)

## Контекст и цель

Интеграция Stock Bot ↔ фотоген-агент уже работает: кнопка «🎨 Создать карточку»
ставит задачу, фотоген генерит карточку и присылает владельцу с кнопкой
«✅ Опубликовать в канал» (режим подтверждения, в канал ничего не уходит без нажатия).

Сейчас при публикации в канал подпись к файлу — просто имя файла. Нужно: под фото
в канале шла **готовая подпись-цитата** с серией и ценами по типоразмерам — полноценный
контент для группы. Пример (как согласовано):

```
❄️ Mitsubishi Heavy Industries
SRK-ZS · инвертор
──────────────────
7  —  39 990 ₽
9  —  45 990 ₽
12 —  52 990 ₽
18 —  78 990 ₽
24 —  94 990 ₽
```

## Решения (согласованы с владельцем)

1. **Цена в подписи** — по той же шкале наценки, что и для списка (регрессивная
   −1/−3/−5/−7%, прогрессивная +1…+10%). Цена типоразмера = `marked_price(опт, %)`.
2. **Где кнопка** — «🎨 Создать карточку» переезжает на экран ПОСЛЕ выбора % (рядом с
   «✅ С характеристиками / 📄 Без»), чтобы знать выбранную наценку.
3. **Подпись типоразмера** — числом (7/9/12/18/24), как говорит владелец.
4. **Превью = публикация** — в личном сообщении владельцу подпись та же, что уйдёт
   в канал (владелец видит точный текст до нажатия «Опубликовать»).
5. **Канал не отключаем** — публикация только по кнопке (режим подтверждения уже есть).

## Архитектура и поток данных

Цены есть только в Stock Bot; публикует фотоген-бот (цен не имеет). Поэтому:

```
Stock Bot (callback c|code|bidx|sidx|pct)
  └─ строит подпись (серия + типоразмеры + цены по %)
  └─ fotogen_bridge.submit_card(..., caption=<текст>)
        │ POST /api/submit-job (новое поле формы caption)
        ▼
фотоген vps_api: INSERT ... caption=...   (новая колонка jobs.caption)
        ▼ агент генерит карточку (~2 мин), result готов
фотоген vps_bot.result_sender (conditioner):
  └─ владельцу карточка + caption как подпись + кнопки [✅][🔄][🗑]
фотоген vps_bot publish:
  └─ в канал: send_document(caption=row["caption"], parse_mode=HTML)
```

Подпись хранится один раз (посчитана в момент создания, с корректными ценами) и
используется и в превью владельцу, и при публикации. Пусто → откат на имя файла.

**Почему отдельное поле, а не `specs`:** `specs` — это плашки НА картинке (промпт
`{{SPECS}}`), другое назначение; смешивать нельзя.

## Формат подписи

- Строка 1: `❄️ <Бренд>`
- Строка 2: `<короткая серия>` + ` · инвертор`, если инвертор определён
- Разделитель `──────────────────`
- По одной строке на типоразмер, по возрастанию: `<число> — <цена с наценкой> ₽`
- Всё обёрнуто в `<blockquote>` (HTML). Длина ≤ 1024 (для серии всегда влезает).
- Бренд/серия экранируются (`html.escape`), поставщик/наценка НЕ раскрываются.

### Источник номера типоразмера
Из `btu_calc` (мощность охлаждения). В `db.py` добавить `p.btu_calc` в SELECT.
Правило: нормализовать к тысячам BTU (если `btu_calc` уже < ~100 — это и есть размер
в тысячах; если > ~1000 — делим на 1000), затем привязать к ближайшему стандартному
из `[7, 9, 12, 18, 24, 36, 48, 60]`. Если значение не привязывается осмысленно —
для этой позиции запасной вариант: короткое имя модели вместо числа (карточку не ломаем).

> Проверка на проде: на первой реальной серии глазами сверить номера и цены
> (живой запрос к каталогу требует отдельного разрешения владельца).

## Граничные случаи
- Пустой `caption` (например, фото отправлено напрямую в фотоген-бот, не через Stock Bot)
  → поведение как сейчас (имя файла / стандартный текст). Не падаем.
- Позиция без распознаваемого btu → запасное имя вместо числа.
- Подпись с `<blockquote>` шлётся с `parse_mode=HTML`; для документа Telegram это допустимо.

## Тестирование
- Юнит-тесты `channel_caption` (Stock Bot): snap btu→размер, формат строк, сортировка,
  цена = `marked_price(opt, pct)`, экранирование, инвертор вкл/выкл. Без БД/сети.
- Фотоген: контракт хранения/чтения `caption` (как redo/retry в `test_modes.py`),
  endpoint с полем `caption`.
- Прод: реальная карточка → сверить номера/цены → опубликовать.

## Вне объёма
- Фото vs документ в канал — оставляем как сейчас (`send_document`, без сжатия).
- Площадь (м²) и BTU-подпись — отклонены, выбран формат «числом».
- Авто-публикация без подтверждения — не делаем (режим подтверждения сохраняется).
