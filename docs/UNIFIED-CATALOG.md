# Единый каталог Breez и Daichi

Существующий бот получает корневое меню `/menu` → группа → вид → товар.
`/catalog` открывает тот же каталог, `/excel` присылает файл, `/series` сохраняет
старое меню серий с фотогенератором. Карточка конкретного товара: ТТХ/УТП/фото
либо карточка для пересылки клиенту с выбранной наценкой. В клиентской карточке
нет закупочной цены, названия поставщика и складского количества.

## Источники и цены

Прямые API, все виды товаров без фильтра `btu` и без ограничений категорий сайта.
Breez: `leftoversnew/`, только склад «Бриз Крым», закупочная `base`; `products/`,
`categories/`, `brands/`, `tech/?id=<внутренний id>` для описаний, фото, УТП, ТТХ.
Запись из остатков без метаданных тоже сохраняется, помечена «Без категории
поставщика». ТТХ кешируются между синхронизациями.

Daichi: склад определяется через `stores/get/`, точный XML_ID сверяется в каждом
товаре; имя в живом API — «Симферопль». `products/get/` даёт складской
`STORE_AMOUNT` и партнёрскую `BASE`; `productparams/get/` обходится постранично
для фото и ТТХ. `BASE` обозначена как партнёрская цена, МПРЦ хранится отдельно.
Ожидаемые поставки/доставка и Севастополь не суммируются с Симферополем.
Валюта сохраняется; отсутствующая закупочная цена остаётся пустой, розница её
не подменяет. `>50` означает «не менее 50», а не точные 50.

## Общая база агентов

- `output/catalog.sqlite3`: текущие товары, история остатков/цен, даты успешной
  синхронизации каждого поставщика. ID стабилен по поставщику и артикулу.
- `output/catalog.json`: доступные товары, фото, ТТХ, УТП, исходные записи API,
  дата источника. Полная выгрузка для контент-агента без ключей поставщиков.
- Существующий защищённый API тендерного агента при `CATALOG_ENABLED=true`
  читает ту же базу; URL и Bearer-аутентификация сохраняются. Добавлены валюта,
  группа/вид, фото, УТП, реальные ТТХ и дата последней успешной синхронизации.
- Excel: сводка и все остатки, сортировка группа → вид → бренд → модель →
  поставщик → артикул, закреплённый заголовок и фильтры. Цены/количество — числа.

Обновление каждого поставщика атомарное. При сбое старая выгрузка сохраняется,
а утреннее сообщение явно сообщает о сбое и датах оставшихся данных.

## Настройка

В существующем `.env` бота:

```
CATALOG_ENABLED=true
SUPPLIER_ENV_FILE=/opt/oasis/.env
CATALOG_DB=output/catalog.sqlite3
CATALOG_JSON=output/catalog.json
```

Ключи используются на сервере из существующих `.env`; в репозиторий не попадают.
Отдельный запуск синхронизации: `python -m stock_report_bot.supplier_catalog`.
Утренний запуск: прежний `run_daily.sh` → `stock_report_bot.main`.
Сетевые обёртки существующего бота сохраняются.

Расписание: `catalog-morning.timer`, ежедневно **08:30 Europe/Moscow**.
Перед включением проверить, что нет старого cron/timer с тем же отчётом.
После установки выполнить `systemctl daemon-reload` и
`systemctl enable --now catalog-morning.timer splithub-menu-bot.service`.
Ключ фотогенератора и его сервер остаются существующими; генерация вызывается
только кнопкой пользователя в `/series`, сама синхронизация ничего не генерирует.

Откат: `CATALOG_ENABLED=false`, вернуть прежнее расписание и перезапустить
`splithub-menu-bot.service`. Сайт и его база не изменяются.
